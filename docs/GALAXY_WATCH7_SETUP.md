# Galaxy Watch7 — setup with Gadgetbridge

Gadgetbridge can run a Galaxy Watch7 as its only companion, but it cannot perform the watch's
initial setup wizard. The watch has to be enrolled once by Samsung's Galaxy Wearable app, and
you have to read one value off the watch afterwards. No root is required, on either device.

Plan for the whole procedure:

1. Enroll the watch once with Galaxy Wearable
2. Read the **companion node ID** off the watch (needs adb, no root)
3. Enter it in Gadgetbridge and disable the Samsung apps

Budget about 20 minutes, most of it Samsung's setup wizard.

---

## Why a node ID is needed at all

During setup the watch memorises the Wear "node ID" of the phone that enrolled it — an
8-character hex string such as `24473012`, generated by Google Play services. From then on the
watch accepts **only** that ID and hangs up on anything else, within milliseconds, without
explanation. Gadgetbridge announces its own ID by default, so the watch drops it.

The value is not derivable from anything on the phone, and the watch only transmits it once a
connection is already established — which cannot happen while the ID is wrong. So it has to be
read once and entered by hand, much like the pairing key for some other watches.

---

## Step 1 — Enroll the watch with Galaxy Wearable

Install **Galaxy Wearable** from the Play Store and pair the watch normally. It will pull in a
device-specific plugin during setup, so the phone needs internet.

Run the wizard through to the end, until the watch shows its watch face. You can decline the
Samsung/Google account linking and any optional location or diagnostics consent — none of it is
required. Do not abort partway: a half-finished wizard leaves the watch in a state where it
keeps asking to start over.

## Step 2 — Read the companion node ID

You need `adb` on a computer ([Android platform tools][adb], no root). The watch has to reach
your computer over Wi-Fi.

[adb]: https://developer.android.com/tools/releases/platform-tools

**Enable developer options on the watch:** Settings → About watch → Software information → tap
**Software version** seven times.

**Enable wireless debugging:** Settings → Developer options → **Wireless debugging** → on. Open
**Pair new device**; the watch shows a pairing code plus an IP address and port.

**Pair and connect from your computer.** Use the address and port from the pairing screen for
`adb pair`, then the address with the port from the main wireless-debugging screen (they differ)
for `adb connect`:

```sh
adb pair 192.168.1.50:37123      # enter the 6-digit code when prompted
adb connect 192.168.1.50:5555
adb devices                      # the watch should be listed
```

**Provoke a rejected connection.** The watch only names the expected ID when something connects
with the wrong one, so let Gadgetbridge try. On the *phone*: disable Galaxy Wearable (Settings →
Apps → Galaxy Wearable → Disable) and the watch plugin next to it, then open Gadgetbridge and
tap the watch entry. It will fail to connect — that is the point.

**Read the ID** from the watch's log:

```sh
adb logcat -d | grep "Mismatched node"
```

```
Wear_Transport: Mismatched node is attempting to connect:
                clientNodeId is 24473012 and message nodeId is a1b2c3d4
```

`clientNodeId` is the value you need — `24473012` above. (`message nodeId` is what Gadgetbridge
announced, which is the wrong one.) If nothing matches, make sure Gadgetbridge actually tried to
connect, then repeat with `adb logcat -c` beforehand to clear old noise.

Turn wireless debugging back off on the watch when you are done.

## Step 3 — Enter it in Gadgetbridge

In Gadgetbridge: the watch's **⚙ settings → Pairing → Companion node ID**. Enter the value and
connect. The watch should report as connected and start syncing.

Keep Galaxy Wearable and the watch plugin **disabled** — two companions fighting over the single
Bluetooth channel makes the connection flap roughly once a second. Disabling is enough; you do
not have to uninstall them, and disabling is easy to undo if you ever want the stock app back.

---

## Troubleshooting

**Connects, then drops after a second, over and over.** Something else is holding the channel.
Check that both Samsung apps are disabled *and* not running (disabling does not kill a running
process — force-stop them too). On some phones Google Play services keeps its own Wear
connection alive. Stop it under Settings → Apps → Google Play services → Permissions → Nearby
devices → Don't allow — no adb needed, it is an ordinary runtime permission. The cost is that
other Play services Bluetooth features stop working too, Fast Pair and Find My Device among
them; re-allowing it is a single toggle.

**Still dropping, and the watch log says `Mismatched node`.** The node ID is wrong. It changes
whenever the watch is re-enrolled, so if you reset the watch or paired it to another phone in
the meantime, read it again.

**The watch is stuck asking to finish setup on your phone.** It was reset or unpaired and needs
the stock wizard again — Gadgetbridge cannot complete that step. Re-enable Galaxy Wearable, run
the setup through, then come back to step 2.

**The watch says it is disconnected.** Check whether Gadgetbridge is actually connected — the
watch reports itself as companion-less exactly while nothing holds the session, including the
moments right after Gadgetbridge restarts. If Gadgetbridge shows the watch as connected, the
watch agrees.
